# Platform PKI & Secrets Management

This document covers the full trust architecture for the Operations Planning platform:
certificate generation, trust distribution, secrets validation, and how everything
works across local Docker and AKS environments.

---

## Overview

The platform uses a self-signed local Certificate Authority (CA) in development and a
real CA in production. All services trust the platform CA at image build time — no
runtime certificate mounts are required.

```
┌─────────────────────────────────────────────────────────────┐
│                     Platform CA (local-ca.crt)              │
│         Committed to git — imported into every image        │
└────────────────────────┬────────────────────────────────────┘
                         │ signs
                         ▼
┌─────────────────────────────────────────────────────────────┐
│              Wildcard Server Cert (local.crt)               │
│  *.ops.local — generated locally, served by Traefik        │
└─────────────────────────────────────────────────────────────┘
```

---

## Directory Structure

```
infrastructure/
└── certs/
    ├── .gitignore          # ignores *.key, server/ — allows trust/local-ca.crt
    ├── trust/
    │   ├── .gitignore      # ignores *.key
    │   └── local-ca.crt   # COMMITTED — imported into images at build time
    └── server/
        ├── .gitignore      # ignores everything (generated files)
        ├── local.crt       # generated by setup.sh — NOT committed
        └── local.key       # generated by setup.sh — NOT committed
```

**Rule**: Private keys (`*.key`) are never committed. The CA public cert (`local-ca.crt`)
is committed so it can be included in Docker image builds from CI.

## Flow 1: First-Time Developer Setup

```
Developer clones repo
        │
        ▼
cd deployment/compose && ./setup.sh
        │
        ├─► Checks for OpenSSL — exits with install instructions if missing
        │
        ├─► Generates infrastructure/certs/trust/local-ca.crt  (committed on next push)
        │   Generates infrastructure/certs/trust/local-ca.key  (gitignored)
        │
        ├─► Generates infrastructure/certs/server/local.crt    (gitignored)
        │   Generates infrastructure/certs/server/local.key    (gitignored)
        │
        ├─► Copies .env.example → .env (if .env does not exist)
        │
        ├─► Validates .env: lists any CHANGE_ME_BEFORE_USE values
        │
        └─► Adds /etc/hosts entries (requires sudo):
            127.0.0.1  auth.ops.local
            127.0.0.1  admin.ops.local
            127.0.0.1  config.ops.local

Developer fills in .env secrets
        │
        ▼
docker compose up --build
        │
        ▼
All services healthy — HTTPS works for all *.ops.local domains
```

**One-time browser trust** (after setup):
```sh
# Firefox
for dir in ~/.config/mozilla/firefox/*/; do
  certutil -A -n "ops.local Dev CA" -t "CT,," \
    -i ../../infrastructure/certs/trust/local-ca.crt \
    -d "sql:$dir"
done
# Restart Firefox
```

## Flow 2: Docker Image Build (CA Trust Injection)

Every JVM service Dockerfile includes the following block in the `runtime` stage:

```dockerfile
# Runtime stage (runs as root before switching to non-root user)
COPY infrastructure/certs/trust/local-ca.crt /tmp/platform-ca.crt
RUN keytool -importcert -noprompt -alias platform-ca \
    -file /tmp/platform-ca.crt \
    -keystore "$JAVA_HOME/lib/security/cacerts" \
    -storepass changeit && \
    rm /tmp/platform-ca.crt
RUN addgroup -S appgroup && adduser -S appuser -G appgroup -u 1001
USER 1001
```

**What this achieves**: Any HTTPS call the service makes to `*.ops.local` (e.g.,
Spring Boot Admin calling `https://auth.ops.local/realms/operations/...`) succeeds
without SSL errors — in both Docker Compose and AKS.

**Layer caching**: The CA cert layer only invalidates when `local-ca.crt` changes
(expected at most once per environment, not per code change).

## Flow 3: Traefik Certificate Loading

Traefik watches its dynamic configuration directory for certificate changes.

**Volume mounts** (in `deployment/compose/docker-compose.yml`):
```yaml
traefik:
  volumes:
    - ../../infrastructure/certs/server:/etc/traefik/server:ro
    - ../../infrastructure/certs/trust:/etc/traefik/trust:ro
    - ../../infrastructure/traefik/dynamic:/etc/traefik/dynamic:ro
```

**Dynamic TLS config** (`infrastructure/traefik/dynamic/tls.yml`):
```yaml
tls:
  stores:
    default:
      defaultCertificate:
        certFile: /etc/traefik/server/local.crt
        keyFile: /etc/traefik/server/local.key
```

**Certificate rotation** (no service restarts needed):
```sh
# 1. Regenerate server cert
./setup.sh --renew
# 2. Reload Traefik (picks up new cert from watched directory)
docker compose kill -s SIGHUP traefik
```
Application containers are unaffected.

## Flow 4: Secret Validation

The `setup.sh` script checks `.env` for placeholder values at any time:

```sh
./setup.sh --check
```

Output example:
```
Checking secrets in .env...
  MISSING: KEYCLOAK_ADMIN_PASSWORD
  MISSING: KC_DB_PASSWORD
  MISSING: POSTGRES_PASSWORD

3 secret(s) need to be set before running docker compose up.
Edit deployment/compose/.env and replace CHANGE_ME_BEFORE_USE values.
```

**What counts as "missing"**: Any variable with value exactly equal to
`CHANGE_ME_BEFORE_USE`. Whitespace differences do not exempt a value.

The check runs automatically at the end of `./setup.sh`. It does not block
`docker compose up` — that choice belongs to the developer.

## Flow 5: Adding a New Service

1. Add the CA import block to the service's `Dockerfile` in the `runtime` stage.

   **JVM service** (Spring Boot, Kotlin — uses `keytool`):
   ```dockerfile
   FROM eclipse-temurin:21-jre-alpine AS runtime
   COPY infrastructure/certs/trust/local-ca.crt /tmp/platform-ca.crt
   RUN keytool -importcert -noprompt -alias platform-ca \
       -file /tmp/platform-ca.crt \
       -keystore "$JAVA_HOME/lib/security/cacerts" \
       -storepass changeit && \
       rm /tmp/platform-ca.crt
   RUN addgroup -S appgroup && adduser -S appuser -G appgroup -u 1001
   USER 1001
   ```

   **Non-JVM service** (Debian/Ubuntu base — uses system CA store):
   ```dockerfile
   FROM <base-image> AS runtime
   USER root
   COPY infrastructure/certs/trust/local-ca.crt /usr/local/share/ca-certificates/platform-ca.crt
   RUN update-ca-certificates
   USER <original-user>
   ```

2. Declare any new secrets in `deployment/compose/.env.example` with
   `CHANGE_ME_BEFORE_USE` and a comment describing the secret's purpose.
3. Run `./setup.sh --check` to verify the new secrets appear in the validation output.
4. The service trusts the platform CA automatically on the next `docker build`.

No other steps are required.

## Flow 6: AKS Production Deployment

In production, the same environment variable names are used but sourced from
Kubernetes Secrets instead of a `.env` file.

```
CI builds image using infrastructure/certs/trust/local-ca.crt
    │
    │   ── Option A (repo-committed CA): use the committed local-ca.crt as-is
    │      Works if the self-signed dev CA is intentionally included in prod images.
    │
    │   ── Option B (CI secret override): inject the real production CA at build time
    │      Store the prod CA PEM in a GitHub Actions secret named PROD_CA_CERT.
    │      CI writes it to the expected path before the Docker build step.
    │
    ▼
Image is pushed with production CA in its truststore
    │
    ▼
AKS Pod environment variables come from Kubernetes Secrets
(same variable names as .env — no code changes needed)
    │
    ▼
Traefik server cert comes from cert-manager or Azure Key Vault
mounted at the same container path (/etc/traefik/server/)
```

**Option B — Overriding `local-ca.crt` via a CI secret** (GitHub Actions example):

```yaml
# In .github/workflows/build-images.yml, add before the Docker build step:
- name: Inject production CA cert
  if: github.ref_name == 'main'
  run: |
    echo "${{ secrets.PROD_CA_CERT }}" > infrastructure/certs/trust/local-ca.crt
```

Then push the production CA PEM to GitHub:
```sh
gh secret set PROD_CA_CERT < /path/to/your/production-ca.crt
```

Images built on `main` will contain the production CA; images built on feature branches
use the committed dev CA. No Dockerfile changes are needed.

**Interface contract**: The environment variable names and certificate mount paths
defined in [`specs/004-zero-trust-pki/contracts/pki-interface.md`](../../../specs/004-zero-trust-pki/contracts/pki-interface.md)
are stable across both environments.

## Flow 7: Certificate Expiry & Rotation

| Cert | Validity | Rotation procedure |
|------|----------|--------------------|
| CA (`local-ca.crt`) | 10 years | `./setup.sh --renew-ca` → rebuild all images → re-import in browser |
| Server (`local.crt`) | 2 years | `./setup.sh --renew` → `docker compose kill -s SIGHUP traefik` |

**CA rotation** is disruptive (all images must be rebuilt) — expected at most once a
decade for dev environments.

**Server cert rotation** is non-disruptive — Traefik reloads the cert without
restarting any application container.
