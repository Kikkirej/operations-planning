# Application PostgreSQL

Shared relational database for all application services. This instance is entirely
separate from the Keycloak-PostgreSQL instance used by the identity provider.

## Purpose

Provides UUID-keyed relational data storage with per-service schema isolation enforced
at the database level. Each service owns exactly one schema; no service may read from or
write to another service's schema.

## Configuration Reference

| Environment Variable | Description | Default |
|---------------------|-------------|---------|
| `APP_POSTGRES_DB` | Application database name | `app_db` |
| `APP_POSTGRES_USER` | Superuser name | `postgres` |
| `APP_POSTGRES_PASSWORD` | Superuser password | **Required — no default** |

Set these in `deployment/compose/.env` (copied from `.env.example`). Never hardcode
credentials in source files.

## Schema Ownership Model

On first start, the bootstrap script (`infrastructure/postgres/init/01-init-app-role.sql`)
creates a shared `app` role with LOGIN. Each service is responsible for creating its own
role and schema on startup:

```sql
-- 1. Service-specific role (run in migration)
CREATE ROLE svc_example WITH LOGIN PASSWORD '...' NOINHERIT IN ROLE app;

-- 2. Service-owned schema
CREATE SCHEMA IF NOT EXISTS svc_example AUTHORIZATION svc_example;

-- 3. Schema-scoped grants only
REVOKE ALL ON SCHEMA public FROM svc_example;
GRANT USAGE, CREATE ON SCHEMA svc_example TO svc_example;
```

All entity tables in `svc_example.*` MUST use a UUID primary key:

```sql
CREATE TABLE svc_example.orders (
    id UUID PRIMARY KEY,
    -- ... service-specific columns
);
```

UUID values are generated by the owning service (e.g., UUID v4); the database enforces
the type constraint only.

## Startup

```bash
cd deployment/compose
docker compose up -d app-postgres
docker compose ps app-postgres   # wait for Status: healthy
```

## Shutdown

```bash
docker compose stop app-postgres
```

**Destroy data** (irreversible):
```bash
docker compose down -v app-postgres
```

## Integration Tests

```bash
docker compose run --rm test-runner sh infrastructure/postgres/test/postgres-isolation-test.sh
```

Tests cover: `app` role bootstrap, UUID PK enforcement, CRUD in owned schema,
cross-schema access rejection.

## Troubleshooting

**Container fails health check**: Check `docker compose logs app-postgres` for errors.
Confirm `APP_POSTGRES_PASSWORD` is set in `.env`.

**Permission denied on cross-schema access**: Expected behaviour — the schema isolation
is working correctly. Each service must only use its own schema.

**`app` role does not exist after startup**: The init script runs only on first start
(empty data directory). If the volume already exists, the script will not re-run. To
re-apply: `docker compose down -v app-postgres` then `docker compose up -d app-postgres`.

**Kubernetes**: Credentials are read from a Secret named in `values.yaml`
(`postgres.auth.existingSecret`). Create the Secret before deploying:

```bash
kubectl create secret generic postgres-secret \
  --from-literal=POSTGRES_PASSWORD=<secret> \
  -n ops
```
